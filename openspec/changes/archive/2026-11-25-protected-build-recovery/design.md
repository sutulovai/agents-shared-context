# Design

The local veto marks initial establishment until Redis answers the first exclusive request. Later duplicate checks compare the ownership token and exact request in Redis, then recheck local identity after the response.

Stage attempts are remembered before transmission. A known refusal removes only bookkeeping created by that attempt; an ambiguous reply is settled by call identity after completion. A protected shell call rejected before launch queues abandonment without relying on an after callback.

Protected builds do not retry as ordinary builds if the expected grant is lost or unavailable. Other work retains fail-open behavior. Exclusivity covers only operations still tracked by participating plugins; no restart barrier or persistent handoff is added.
